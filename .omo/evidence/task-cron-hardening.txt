1. Problem Diagnosis & Fix Summary:
--------------------------------------------------------------------------------
- Fix 1 (Next Run Advancement & Failure Backoff):
  Implemented next_run advancement and exponential backoff on consecutive failures in CronScheduler::complete_failure.
  - One-shot jobs (once:) are marked completed/disabled (enabled = 0, next_run_at = NULL).
  - Recurring interval and cron jobs compute next_run_after_failure using exponential backoff (10s * 2^(failures-1), clamped between 10s and 3600s).
  - next_run_at is strictly in the future: max(scheduled_next, now + backoff), preventing tight loop re-firings.
  - Consecutive failures are queried atomically from recent cron_runs within the transaction.

- Fix 2 (Database Indexing on cron_runs):
  Added migration `migrations/0005_cron_runs_indexes.sql`:
  - `idx_cron_runs_job_status ON cron_runs(job_id, status)`
  - `idx_cron_runs_job_attempt ON cron_runs(job_id, attempt DESC)`
  Accelerates MAX(attempt) subquery, lease active checks, and status filtering per schedule evaluation.

- Fix 3 (Execution PATH Augmentation):
  Implemented `build_augmented_path` and `augmented_path_from_environment` defaulting to prepend `/opt/homebrew/bin:/usr/local/bin` (configurable via OMON_EXTRA_PATH / EXTRA_PATH) while preserving inherited PATH.
  Applied to:
  - TerminalTool execution (src/tools/terminal.rs)
  - McpTool stdio child process execution (src/tools/mcp.rs)
  - Cron shell task executor (src/cron/scheduler.rs)
  - Native cron script execution (src/main.rs)
  - Hermes cron script execution (src/main.rs)
